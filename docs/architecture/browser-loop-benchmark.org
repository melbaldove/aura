#+title: Browser loop comparison

Measured on 2026-09-21 with ~agent-browser 0.26.0~ on macOS arm64.

See the [[file:browser-procurement-benchmark.org][procurement comparison]] for a
more complex task that uses the original browser's snapshot and click
controls. It compares successful old-flow and Jev completion times.

The first comparison ran both flows from the edited checkout. Its old-flow
results were not a separate pre-Jev revision test. The check below corrects
that gap. These experiments do not establish a production speedup.

* Original edited-checkout experiment

* Browser control diagnosis

A later replay removed GPT from the test and called the pre-Jev browser FFI
directly with the same form. It confirmed the following behavior with the
installed ~agent-browser 0.26.0~:

- After focusing Name, ~press Control+A~ returned success but left both
  selection positions at 3. The next ~type~ changed ~old~ to ~oldAura~.
- ~Meta+A~, ~Control+a~, ~Meta+a~, and ~ControlOrMeta+A~ also left the text
  unselected in this replay. Plain ArrowLeft and Backspace did work, so the
  replay separately confirmed input focus and ordinary key input.
- Clicking the Blue option returned `DOM.getBoxModel: Could not compute box
  model`. The selected value remained Red.
- Native ~fill~ replaced the Name value with Aura. Native ~select~ changed
  Color to Blue. Both completed without a model request.

The old browser tool exposes ~type~, ~click~, and ~press~, but does not expose
~fill~ or ~select~. It can use JavaScript through ~console~, but these failed
trials kept attempting other input sequences. The Jev adapter uses native
~fill~ and ~select~. Thus, the original comparison mixes form-action support
and action reliability with loop speed. It is not evidence of GPT being slow
on successful browser work.

The exact cause of the modifier-shortcut behavior inside the installed runner
remains unconfirmed. The raw ~browser_control_diagnosis~ records contain the
commands and observed field values. No session-handling code was changed.

* Method

The old flow uses Aura's existing ~agent_loop~ and browser tool dispatcher
from the edited checkout. Its browser tool definition was generated with the
Jev feature flag disabled. The mixed-flow driver then restored that flag
before executing both flows. The old-flow tool description
and parameters match the original code at ~c9bda27~. GPT-5.6 Luna, with low
reasoning, chooses the browser actions. It can use all existing browser actions,
including JavaScript through ~console~.

The new flow enters through ~browser(action="run")~. TypeSafe ~jev-latest~
chooses actions. GPT-5.6 Luna, with low reasoning, supplies field text.
Both flows use Aura's current Codex authentication and browser runner.

The task is: “Replace Name with Aura, choose Blue, and click Apply. Stop when
the result shows Aura blue.” Each trial uses a separate isolated browser session
with a small test form on ~https://example.com~. Each trial replaces the page DOM with the same
form. Name starts as ~old~, Color starts as Red, and the result is empty.
No model receives the fixture source or a prescribed action sequence.
Each trial navigates to the fixture origin and checks the URL before timing.
The session name contains a short timestamp and trial identifier to prevent
reuse. Each trial creates its own cookie and local-storage marker before timing.

Five pairs run in sequence. Odd pairs run the old flow first. Even pairs run
Jev first. Each trial has a 60-second deadline. Browser commands and model
requests use the time left before that deadline. Stream progress cannot extend
the deadline. Failed trials remain in the results.

Timing includes the first observation, model requests, browser commands, and
the flow's final response. It excludes browser startup, page setup, and the
independent test check. The test checks the exact Name value, selected option,
and submitted result. It also checks that the session cookie and local-storage
marker remain present. The raw result records each check separately.
A pass requires those checks to pass and the flow to return without an error.
Timeout durations measure when the trial stopped, not successful completion.

The comparison measures the browser loop. It excludes Discord processing and
the outer model calls that dispatch and verify ~browser(action="run")~.
The old flow receives a short browser-only system instruction and the original
browser tool definition. It does not receive the full production prompt,
conversation history, or other tools. Thus, these results do not measure total
user response time or the exact deployed configuration.

* Repeat the comparison

Supply ~TYPESAFE_API_KEY~ through the process environment. Use the existing
Codex login. Then run:

#+begin_src sh
AURA_BROWSER_BENCHMARK=true AURA_BROWSER_JEV_ENABLED=true \
  TEXT_MODEL=openai-codex/gpt-5.6-luna \
  TYPESAFE_MODEL=jev-latest \
  gleam run -m browser_loop_benchmark
#+end_src

The test prints one ~RESULT~ JSON object per trial. It also prints the old
flow's browser arguments, which contain only test form data. The test closes
its own browser session when it finishes.

The driver is ~test/browser_loop_benchmark.gleam~. Its test-only Erlang helper
uses Aura's existing streaming transport and adds a deadline while retaining
tool calls in each model response.

* Preliminary attempts

The first attempt recorded an old-flow timeout at 60.002 seconds and two Jev
errors at 0.173 and 0.164 seconds. Both Jev errors occurred before a model
request. Inspection found the browser on ~about:blank~, where
~crypto.randomUUID()~ was unavailable. The cause of that page state is not
confirmed. A second old-flow trial was interrupted to inspect the error.

The adapter now creates tokens with ~crypto.getRandomValues()~ when
~crypto.randomUUID()~ is unavailable. The real-browser smoke test now checks
observation and target preparation on ~about:blank~. It passed, along with
the existing local-session and CDP checks. All 113 focused tests passed, and
the Erlang release export passed.

The comparison driver now checks the page before every trial and uses a new
session name for every test invocation. An initial timestamp name exceeded
the browser socket path limit. That attempt stopped during setup, before any
timed trial. The shortened name fits the limit.

An initial five-pair series reused one browser session. After old-flow
timeouts, some Jev trials reported the correct submitted text but failed the
combined independent check. A diagnostic read also timed out while the old
flow was stalled. That series cannot exclude interference between trials.
Its results remain in the raw data. The final series uses a separate session
for each trial and records individual checks. Production session handling
is unchanged.

The first isolated attempt stopped during verification after an old-flow
timeout. Reading ~document.cookie~ raised a ~SecurityError~. Verification now
handles inaccessible storage and browser transport errors as failed checks,
so one failed trial does not stop the remaining trials.

These preliminary attempts are separate from the final five pairs below.

old-flow timeout. The cause of that page state is not confirmed. No model
stream retries occurred in either flow.

The preliminary shared-session series included one successful old-flow trial
at 50.583 seconds. It also included failed Jev verification checks after
old-flow timeouts. Those results are preserved separately; they are not pooled
with the isolated trials.
